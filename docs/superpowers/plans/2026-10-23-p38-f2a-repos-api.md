# P38 F2a: repositories API, lifecycle, collaborators, branches (plan)

Slice F2 of the sc-forge spec is split in two PRs by agreement: **F2a** (this plan: repo
metadata and API, bare-repo lifecycle with reconcilers, collaborators, branch reads, the
`git` runner they need) and **F2b** (smart-HTTP transport through `git http-backend`, hooks,
ref-namespace policy, admission control, process groups, threat-model pass #1; planned
after F2a merges). Spec: `docs/superpowers/specs/2026-10-22-p38-forge-design.md`
("Repository lifecycle", "Server-side Git operations", "Authentication", Appendix A).

## Scope

Routes (all under `/api/v1`, one row each in `routes::ROUTES` with class, scope, actor):

| Route | Scope | Actor / access |
|---|---|---|
| `POST /orgs/{o}/repos` | write:organization | org owner or site admin (row exists, F1) |
| `POST /user/repos`, `GET /user/repos` | write:user / read:user | create: caller owns; list: every repo the caller can read (owned, collaborator, org-owned) |
| `GET /orgs/{o}/repos` | read:organization | 200 for any existing org, listing only repos the caller can read (see "Listings") |
| `GET /repos/{o}/{r}` | read:repository | read |
| `PATCH /repos/{o}/{r}` | write:repository | admin on the repo |
| `DELETE /repos/{o}/{r}` | write:repository | owner-level: owning user, org owner, site admin (not an admin collaborator, as Gitea's `reqOwner`) |
| `GET /repos/search` | read:repository | filtered by caller access |
| `GET /repos/{o}/{r}/collaborators`, `.../{u}/permission` | read:repository | admin |
| `PUT\|DELETE /repos/{o}/{r}/collaborators/{u}` | write:repository | admin |
| `GET /repos/{o}/{r}/branches`, `.../branches/{b..}` | read:repository | read (`{b..}` is a tail capture: branch names contain `/`, recorded E#5) |
| `DELETE /repos/{o}/{r}/branches/{b..}` | write:repository | write; the default branch is refused with 403 `can not delete default branch` (recorded Q#15); protection arrives with F4's policy function |

Out of F2a (later slices): git transport (F2b), tags/refs/commits/trees/contents/archive (F3),
pulls/statuses/merge/protection (F4). Teams and web UI stay out of scope.

## Data model (migration 2)

```sql
CREATE TABLE repos (
  id INTEGER PRIMARY KEY AUTOINCREMENT,            -- immutable; the directory name
  owner_id INTEGER NOT NULL REFERENCES users(id),
  name TEXT NOT NULL, lower_name TEXT NOT NULL,
  description TEXT NOT NULL DEFAULT '', website TEXT NOT NULL DEFAULT '',
  default_branch TEXT NOT NULL,
  state TEXT NOT NULL CHECK (state IN ('creating','live','deleting')),
  created_unix INTEGER NOT NULL, updated_unix INTEGER NOT NULL,
  UNIQUE (owner_id, lower_name)                    -- also covers creating/deleting rows
);
CREATE TABLE collaborators (
  repo_id INTEGER NOT NULL REFERENCES repos(id) ON DELETE CASCADE,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  mode TEXT NOT NULL CHECK (mode IN ('read','write','admin')),
  PRIMARY KEY (repo_id, user_id));
```

`private` is not stored: every repo is private (spec: no anonymous read; `private:false`
accepted and answered `true`). A `creating`/`deleting` repo is invisible to every API route
(404) and to git (F2b).

## Access model (one function, shared with F2b)

`access::resolve(conn, user, owner, name) -> Option<Access{repo, perm, is_owner}>` is the only
place that turns (caller, repo) into a permission; the F2b git path calls the same function,
so API and git cannot drift. `perm` is `Read < Write < Admin`: site admin = Admin; the owning
user, or an owner of the owning org = Admin and `is_owner`; else the collaborator mode; else
none. Org membership alone grants nothing. Repo routes resolve in `dispatch` through a new
`Actor::Repo{owner, repo, min, owner_only}` row field, in this order, before any handler:

1. authentication, then scope (F1 order, unchanged);
2. token with `public-only` -> 403 `token scope is limited to public repos` (recorded R#1),
   before any existence information (individual repo routes only; listings below);
3. repo missing, not `live`, or no access -> the identical 404 (`The target couldn't be
   found.`; foreign token gets what a missing repo gets);
4. visible but below `min`, or `owner_only` without `is_owner` -> 403. The text is pinned from
   a recording where one exists and otherwise a plain `You do not have permission to perform
   this action`; no placeholder reaches a departure.

Collaborator rules (decided here, the recordings only exercise read/write grants):
only Admin may list, add, change or remove collaborators; an admin collaborator may grant any
mode including `admin` and may remove other collaborators, but owner authority never depends
on a collaborator row and cannot be revoked through them; adding the owner (or an owner of the
owning org) as a collaborator is 422; the target must be a user, not an organization (422
`user does not exist [uid: 0, name: x]`, recorded C#17); `permission` must be `read`, `write`
or `admin`, default `write`, anything else 422; a user may not remove their own admin-by-row
access through the last-admin path only if they are the sole admin collaborator and not the
owner (not enforced: the owner can always repair it). Collaborators are returned in the order
they were added (recorded C#18).

## Listings (search, `/user/repos`, `/orgs/{o}/repos`)

All three filter in SQL by the same predicate as `resolve` (owner, org-owner join, collaborator
row, admin = all) intersected with the token: a `public-only` token sees **nothing** (200, empty
data, `X-Total-Count: 0`; recorded R#3), never a 403. `X-Total-Count` is the visible count.
K#54-56 recorded counts that include repos the caller cannot see (11 for an outsider whose body
is empty); sc-forge answers the visible count, a reviewed departure on those exchanges (the
200-for-an-invisible-org itself is kept: F1 already accepts that org existence leaks, recorded
`HasOrgOrUserVisible` vs `GetOrgByName`).

## Git runner (`gitproc.rs`)

The one place a `git` child is spawned (F2b adds the CGI path on the same primitives):
`env_clear`, fixed `PATH`, `HOME=<data>/tmp/home`, `GIT_CONFIG_NOSYSTEM`, `GIT_CONFIG_GLOBAL=/dev/null`,
`GIT_ATTR_NOSYSTEM=1`, `GIT_NO_REPLACE_OBJECTS=1`, `GIT_TERMINAL_PROMPT=0`, `GIT_CEILING_DIRECTORIES=<data>`,
and **always** `--git-dir=<absolute repo dir>` (never discovery: a repo with a missing or corrupt `HEAD`,
the case the reconciler repairs, must not make git walk up to an enclosing repository), per-spawn config through
`GIT_CONFIG_COUNT` (`core.hooksPath=<data>/hooks`, `core.fsync=all`, `core.fsyncMethod=fsync`,
`gc.auto=0`, `core.useReplaceRefs=false`, `receive.fsckObjects=true`), explicit author and
committer identity from the acting user for commit-producing spawns, own process group
(`CommandExt::process_group(0)`), wall-clock timeout that kills the group (`libc::killpg`)
and reaps it, stdout and stderr capped and drained concurrently, a global semaphore of
concurrent children. The semaphore is acquired with a deadline (503 on expiry) before any
stdin is written, stdout/stderr are drained by their own threads (not the blocking pool), the
timeout covers waits and stdin, and every exit path kills the group and reaps it. Inputs:
`repo_dir` is always built from the integer id; **branch names are validated first** by a
`check-ref-format`-equivalent (`refname::branch(name)`: no `..`, no control chars or space,
no `~^:?*[\`, no leading `-`, no trailing `.lock`/`/`/`.`, not `@`, no `@{`), then
addressed as the full ref `refs/heads/<b>` with `show-ref --verify` (never as a revision, so
`main~1` cannot pass); blob and commit-message bytes go through stdin, never argv; commit
identity values (login, email) must contain no NUL, newline, `<` or `>` (and the F1 admin
user create/patch gains the same email check). `for-each-ref` uses a fixed
`--format=%(refname)%00%(objectname)` with explicit `--sort`, not `-z` (not a git option).

Used in F2a for: `init --bare --initial-branch=<b> --template=`, `symbolic-ref HEAD`,
`for-each-ref --format`, `show-ref --verify`, `rev-parse --verify`, `hash-object -w --no-filters --stdin`, `mktree`/`commit-tree` (auto-init),
`update-ref -d` (branch delete), `log -1 -z` (branch object).

## Lifecycle (journaled, crash-safe, serialized)

**Single writer.** `serve` takes an exclusive `flock` on `<data>/.lock` before anything else and
fails if it cannot (a second `serve` or a concurrent reconcile cannot mutate the same
directory). Reconcile runs once, at startup, before the listener is bound; it is also callable
from tests. **Per-repo mutex** (in-process map keyed by repo id): create-finalize, delete,
PATCH default_branch and branch delete take it, re-check `state = 'live'` under it, and use
conditional SQL (`... WHERE id = ? AND state = 'live'`). The git runner refuses to spawn for a
repo whose row is not `live` (F2b also registers its children for the delete to terminate).

**Create**: insert row `creating` (unique violation -> 409 `The repository with the same name
already exists.`) -> `git init --bare` into `repos/<id>.git` -> optional auto-init commit via
plumbing -> fsync **every file and directory of the new tree** (about ten entries with
`--template=`) and `repos/`, propagating any fsync error -> set row `live` -> 201. Any failure
before `live` rolls back in-process (remove directory, delete row) and answers 500, so a failed
create never blocks the name; if the rollback itself fails the row stays `creating` and the
next startup reconcile finishes it.
**Delete** (owner-level): row `deleting` -> rename the directory into `trash/<id>.git` -> fsync
both parents -> transactional row delete (collaborators cascade) -> remove the trash entry
(failure is logged; the startup reconcile removes it). A failed rename is rolled back to `live`.
**PATCH default_branch**: under the repo mutex, `show-ref --verify refs/heads/<b>` must succeed
(422 otherwise: departure), write bare `HEAD` (`symbolic-ref`), then the conditional row update;
the row is the authority on mismatch. **PATCH `name`** (rename) is rejected with 422
`repository rename is not supported` (departure; M#42-45/49-51), never silently accepted. Other
Gitea fields (`has_*`, `allow_*`, `private`, ...) are accepted and ignored, answered with the
fixed values (recorded C#6-8).

**Reconciler** (`lifecycle::reconcile`, startup only, all outcomes logged), by the spec's table
with these amendments: **every `creating` row is rolled back** (directory removed, row deleted;
the row does not record `auto_init`, so a half-initialized repo can never be promoted, and the
client never saw a 201 for it); a directory in `repos/` with no row at all is **moved to
`<data>/orphans/<id>.git` and logged, never deleted** (a restored or recreated `forge.db` must
not erase repositories); `deleting` + directory present -> resume at the rename; `deleting` +
trash present -> finish by deleting the row; trash with no row -> removed; `deleting` with
neither -> row deleted; a `live` row whose `HEAD` differs from `default_branch` ->
`symbolic-ref` repair; a `live` row whose directory is missing -> logged and left (never
silently dropped).

## Names (extend `names.rs`)

Repo names: `[A-Za-z0-9._-]`, at most 100 chars, `.` and `..` reserved, suffixes `.git`,
`.wiki`, `.rss`, `.atom` rejected with Gitea's texts (`name is reserved [name: .]`,
`name pattern is not allowed [pattern: *.git]`, `[Name]: AlphaDashDot`, `[Name]: MaxSize`);
leading `.`/`-`, `a..b`, and `api`/`admin`/... accepted (repos live under their id).
Case-insensitive uniqueness per owner via `lower_name`. Lookups are case-insensitive for owner
and name (recorded M#3-5).

## Repo JSON

One `repo_json(app, repo, owner, perm, empty)` builds the ~70-key object recorded in C#0
(constants for the Gitea feature flags; `private`, `permissions` {admin,push,pull} from
`Perm`, `empty` from `rev-parse --verify HEAD` live, `default_branch`, URLs from the
normalized base, `ssh_url` as `ssh://<host>/<o>/<r>.git`, `size` 0, `watchers_count` 1).
Search wraps it as `{"ok":true,"data":[...]}` with `X-Total-Count`; user/org repo lists are
bare arrays. Branch object per E/D fixtures.

## Risks and open points

- `Actor::Repo` puts repo resolution in `dispatch`; a test enumerates every row whose pattern
  has `{r}` and fails unless it uses `Actor::Repo`.
- Known limit: a push that deletes the branch a concurrent PATCH just chose as default can
  leave `HEAD` pointing at a missing branch (repo reads as `empty`); the row stays the
  authority and the F2b pre-receive hook refuses deleting the row's default branch.
- Per-source failure of the git runner under load is a 503, not a queue: admission is bounded
  and has a deadline.
- Repo-name case: store and compare lower-cased; the displayed `name` keeps the stored case.
- `git init --bare` inherits the host's templates unless `--template=` is empty; the runner
  always passes it, and a test asserts the new repo has no `hooks/*.sample` and no config
  beyond the minimum.
- fsync durability is asserted by code review plus the crash-point tests, not by power-loss
  tests (F5).
- Blocking work: handlers already run on blocking threads; the git runner is synchronous in
  F2a (F2b adds async streaming for the CGI).
